# 수익화 감사 — Codex 조사 지시 (읽기 전용)

사용자 목표: **"크리에이터가 실제로 돈을 내는 시스템"**. 전략을 세우기 전에 **코드가 말하는 사실**을 모은다.

## 규칙
- 소스 수정 금지, 커밋 금지. 쓸 수 있는 파일: `docs/work/monetization-audit.md` 하나.
- Gradle 을 돌리지 말 것(Claude 가 같은 작업트리에서 전체 테스트 중 — 빌드 디렉터리 충돌).
- 추정과 확인을 구분하고, 모든 주장에 `파일:줄`.

## 조사 질문
1. **요금제별 실제 차이**: Free/Starter/Pro/Business 가 코드에서 무엇을 막고 무엇을 허용하는가
   (업로드 수, 저장 용량, 연결 채널 수, AI 크레딧, 기능 게이트). 마케팅 문구·프런트 표시와 **백엔드 강제**가 일치하는가?
   화면에만 있고 서버가 강제하지 않는 한도, 반대로 서버는 막는데 화면이 안 알려주는 한도를 모두 적을 것.
2. **돈을 내게 되는 순간(전환 지점)**: 사용자가 한도에 부딪히는 곳마다 무슨 일이 일어나는가 —
   업그레이드 안내가 뜨는가, 그냥 오류인가, 결제 화면까지 몇 번 클릭인가. `PLAN_LIMIT_EXCEEDED`·`STORAGE_QUOTA_EXCEEDED`·
   `InsufficientCreditException` 등의 프런트 처리 경로를 추적.
3. **결제 경로가 끝까지 이어지는가**: 가격 선택 → PortOne 결제 → 웹훅 → 구독 활성화 → 권한 반영 → 영수증/해지.
   각 단계의 코드 위치와 **끊기는 곳**. 무료체험(TRIALING)·크레딧 단건 구매 경로도 포함.
4. **유료로 받을 만한 기능 중 이미 있는데 무료로 새는 것**, **유료 표기인데 실제로는 동작하지 않는 것**.
5. **가격 근거**: 원가가 드는 기능(AI 호출, 저장, 쇼츠 렌더) 대비 크레딧·가격이 손해인 곳이 있는가(코드상 단가 상수 기준).

## 결론 형식
- 맨 위에 "돈을 막고 있는 것 Top 5" (영향 큰 순, 근거 포함).
- 이어서 질문 1~5 상세.
