# onGo "Must-Use" 기능 기획서 v3.0 — 크리에이터 락인 전략

> 작성일: 2026-04-07
> 전제: v2 기획서의 "더 좋은 도구" 관점을 넘어서, 크리에이터가 **떠날 수 없는** 이유를 만든다.
> 핵심 질문: "크리에이터가 onGo를 끄면 *하루 안에* 손해를 보는가?"

---

## 0. 전략 전환 — 왜 v2는 부족한가

v2 기획은 "경쟁사보다 더 나은 기능"에 집중했다. 그러나 크리에이터는 도구를 자주 갈아탄다.
**락인을 만드는 것은 기능의 우월성이 아니라 4가지 의존성이다:**

| 의존성 종류 | 정의 | 예시 |
|------------|------|------|
| 💰 **수익 의존성** | 끄면 *직접* 돈을 잃는다 | Stripe, AdSense |
| 📊 **데이터 의존성** | 시간이 쌓일수록 가치가 커지고, 못 가져간다 | Google Analytics, Notion |
| 👥 **관계 의존성** | 팬/팀/브랜드와 onGo 안에서만 연결됨 | Patreon, Discord |
| ⏱️ **워크플로 의존성** | 매일의 루틴이 onGo 없이 안 돌아간다 | Slack, Linear |

v3는 이 4축 각각에 강력한 락인 기능을 박는다.

---

## 1. 💰 수익 의존성 (Revenue Lock-in)

### M1. 통합 수익 정산 허브 (Revenue Reconciliation Hub) ⭐⭐⭐
> "내 모든 플랫폼 수익이 onGo 한 화면에 들어오고, 세금 계산서까지 발행된다"

**Why must-use**: YouTube AdSense, TikTok Creator Fund, 인스타 보너스, 광고 협찬, 슈퍼챗… 크리에이터는 매월 5~10개 수익원을 수기 정산한다. onGo가 자동 수집 + 환율 환산 + 세금 분리 + 정산서 PDF를 제공하면, **세무 신고철에 끄면 안 되는 도구**가 된다.

**구현**:
- 플랫폼 API + 영수증 OCR 업로드 (수동 보완)
- 월별 자동 정산서 PDF (사업자/프리랜서 양식)
- 부가세/원천세 자동 분리, 환율 일일 스냅샷
- "올해 누적 매출" 위젯 → 대시보드 상시 노출
- **테이블**: `revenue_streams`, `revenue_entries`, `tax_reports`(신규 V42)

**락인 강도**: ★★★★★ — 1년치 데이터가 쌓이면 절대 못 옮긴다.
**API**: `GET /api/v1/revenue/reconciliation?month=YYYY-MM`, `POST /api/v1/revenue/tax-report`

---

### M2. 브랜드 딜 CRM & 인보이스 자동화
> "협찬 제안 메일 → 견적 → 계약서 → 인보이스 → 입금 확인"의 풀 사이클 관리

**Why must-use**: 크리에이터의 가장 큰 페인은 "광고주와의 메일/엑셀/카톡 난장판". onGo가 인박스에서 협찬 메일을 자동 분류 + 단가 추천 + 전자 계약 + 인보이스를 발행해주면, 광고주 측에서도 "onGo 인보이스로 보내주세요" 요구가 생긴다 → 락인 가속.

**구현**:
- Gmail/Naver 메일 OAuth → 협찬 메일 자동 라벨링
- 단가 추천(M1의 데이터 기반) → 견적서 PDF
- 전자 서명(DocuSign 대체) — 단순 hash + IP 로그
- 인보이스 PDF + Stripe Connect 송금 링크
- **테이블**: `brand_deals`, `deal_invoices`, `deal_contracts`(V43)

**락인 강도**: ★★★★★ — 광고주 연락처 + 계약 이력이 onGo에만.

## 2. 📊 데이터 의존성 (Data Lock-in)

### M3. 크리에이터 OS — 영구 콘텐츠 그래프
> "내가 만든 모든 영상의 메타, 썸네일, 스크립트, 성과, A/B 결과가 onGo에 영구 저장"

**Why must-use**: 크리에이터는 5년 후에도 "3년 전 그 영상 제목 뭐였지?" 검색한다. 플랫폼은 지우거나 알고리즘 가린다. onGo가 **개인 콘텐츠 위키**가 되면 못 떠난다.

**구현**:
- 모든 업로드 영상의 메타/썸네일/스크립트/태그 영구 백업
- 풀텍스트 검색 (PostgreSQL FTS 이미 있음)
- 영상 간 관계 그래프(시리즈/리메이크/리퍼포지)
- "이 영상 패러디" / "이 영상 후속편" 링크
- **테이블**: 기존 `videos` 확장 + `video_relations`(V44), `video_archives`(원본 보존)

**락인 강도**: ★★★★ — 데이터 마이그레이션 비용이 너무 큼.

---

### M4. 크리에이터 헬스 스코어 (일일 100점 만점)
> "오늘 당신 채널 건강도: 87점 (어제 -3점, 이유: 업로드 지연)"

**Why must-use**: Whoop/Apple Health처럼 **매일 확인하는 숫자 하나**를 만든다. 한번 추적 시작하면 끊김 = 데이터 단절 공포.

**구현**:
- 5개 축: 업로드 일관성, 참여율, 구독 증가, CTR, 수익 다양성
- 매일 자정 자동 계산, 30일 잔디
- "연속 7일 80점 유지" 등 스트릭 → 게이미피케이션
- 푸시: "어제 점수 깎인 이유" 1줄 알림
- **테이블**: `health_scores`(V45) — userId, date, score, breakdown JSONB

**락인 강도**: ★★★★ — 스트릭 깨짐 손실 회피 심리.

## 3. 👥 관계 의존성 (Relationship Lock-in)

### M5. 통합 슈퍼팬 CRM (Top Fans Across Platforms)
> "@minji_kim님은 YouTube에서 47회, TikTok에서 23회 댓글, 인스타 좋아요 89회 — 슈퍼팬"

**Why must-use**: 크리에이터는 슈퍼팬을 알아보면 답글 1개로 충성도 폭발시킬 수 있다. 그러나 플랫폼이 분리되어 있어 **누가 슈퍼팬인지 모른다**. onGo가 닉네임/이메일/이미지 매칭으로 통합 프로파일을 만들면, 크리에이터의 "팬 데이터베이스"가 된다.

**구현**:
- 댓글/멘션/DM에서 사용자 식별 → 통합 프로필
- 활동 점수, "최근 7일 활동", 슈퍼팬 배지
- 직접 답글/DM 보내기 (기존 SocialInbox 연계)
- 슈퍼팬 1000명 명단 CSV 내보내기는 Pro+
- **테이블**: `fan_profiles`(V46), `fan_activities`(V46)

**락인 강도**: ★★★★★ — 1년치 팬 데이터는 대체 불가능 자산.

---

### M6. 팀 워크스페이스 + 외부 협업자 게스트
> "편집자/매니저/PD를 초대 + 광고주를 게스트로 — 모두 onGo 안에서"

**Why must-use**: 크리에이터가 1인 → 팀이 되는 순간이 락인의 골든 타임. 편집자가 onGo에 들어와 일을 시작하면, 그 편집자도 onGo가 익숙해진다 = 다른 도구로 못 옮긴다.

**구현**:
- 역할: Owner / Manager / Editor / Viewer / Guest(광고주)
- 영상별 권한, 댓글/승인 워크플로
- 게스트 링크: 광고주가 로그인 없이 영상 미리보기 + 코멘트
- **테이블**: 기존 team 테이블 확장 + `workspace_guests`(V47)

**락인 강도**: ★★★★ — 팀이 클수록 이전 비용 폭증.

## 4. ⏱️ 워크플로 의존성 (Workflow Lock-in)

### M7. 모닝 브리프 (매일 아침 8시 푸시)
> "오늘의 onGo 브리프: 어제 +2,341 구독, 광고주 메일 3건, 코멘트 18건 답변 대기, 추천 업로드 시간 19:00"

**Why must-use**: 크리에이터의 하루를 onGo로 시작하게 만든다. 한번 습관이 되면 끊기 어렵다 (Slack 모닝 알림과 동일 메커니즘).

**구현**:
- Push/이메일/카카오톡 발송 (시간 사용자 설정)
- 5섹션: 어제 성과 / 오늘 할 일 / 인박스 알림 / AI 추천 / 헬스 스코어
- 1탭으로 "오늘의 액션" 시작
- 카카오톡 알림톡 통합 (한국 특화)

**락인 강도**: ★★★★ — DAU 직결.

---

### M8. 단축키 · 명령 팔레트 (Cmd+K 글로벌)
> "어디서든 Cmd+K → 영상 검색, 기능 점프, 광고주 추가, AI 호출"

**Why must-use**: 파워 유저가 "이거 없으면 못 일해"라고 느끼는 순간 락인 완성. Linear/Notion/Raycast 패턴.

**구현**:
- 글로벌 명령 팔레트 (이미 있는 `vue-command-palette` 또는 자체 구현)
- 영상/광고주/팬/캘린더 검색 통합
- AI 호출: "@cmd 내일 8시에 인스타 예약" → 자동 수행
- 50+ 단축키, 사용자 정의 가능

**락인 강도**: ★★★ — 파워 유저 한정이지만 강도 매우 높음.

---

### M9. onGo 모바일 — 답글 전용 라이트 앱 (PWA + 푸시)
> "이동 중에 댓글 답변, 슈퍼팬 메시지, AI 답글 추천 1탭 전송"

**Why must-use**: 크리에이터의 "남는 시간 5분"을 잡는다. 한번 손에 익으면 모바일이 데스크탑보다 자주 열림.

**구현**:
- PWA (이미 있음) 강화 — 답글/인박스/알림 화면만 모바일 최적화
- 푸시 알림 (Web Push API)
- 음성 답글 (STT → AI 다듬기 → 전송)
- 오프라인 큐 (네트워크 복구 시 자동 전송)

**락인 강도**: ★★★★ — 모바일 습관은 가장 끈적함.

## 5. 🌟 차별화 한방 — onGo만의 시그니처

### M10. AI 크리에이터 트윈 (Personal AI Clone)
> "내 과거 영상 1000개로 학습된 AI가 내 말투/관심사로 답글, 스크립트, 아이디어를 생성"

**Why must-use**: 학습 데이터가 쌓일수록 다른 곳에서 흉내낼 수 없는 **개인화된 AI**가 된다. 1년 학습된 트윈은 절대 못 버린다.

**구현**:
- 과거 영상 스크립트/답글/제목 → 임베딩 + few-shot 프롬프트
- 개인 스타일 가이드 자동 추출 (말투, 자주 쓰는 단어, 톤)
- 모든 AI 기능에 "트윈 모드" 토글 — 트윈이 작성한 결과물
- 월 1회 자동 재학습 (신규 콘텐츠 반영)
- **테이블**: `creator_twins`(V48), `twin_training_data`(V48)

**락인 강도**: ★★★★★ — 시간이 곧 자산. 6개월 쓴 트윈 = 못 버림.

## v2와의 관계

v2의 Phase 1~3은 **도구 경쟁력**을 만든다 → 신규 가입을 끌어온다.
v3의 M1~M10은 **떠나지 못하게** 한다 → 가입자를 락인한다.

두 기획서는 충돌하지 않는다. v2를 먼저 완성해서 *유입*을 만들고, v3를 *유지*에 투자하는 것이 정석.

**그러나 자원이 한정되어 있다면, v3 M1(수익 정산)부터 시작해라.** 락인 없는 도구는 결국 더 나은 도구가 나오면 버려진다.
